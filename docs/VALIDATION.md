На ещё одной копии выполнены реальные запросы Kufar: свежая лента, детали и обработка двух объявлений, принудительное обновление рыночной выборки iPhone 12 128GB (24 подходящих предложения). # Проверки 26 ноября 2026 года

Среда: Windows, Python 3.14.6, отдельная `.venv`. Установлены закреплённые `requests 2.34.2`, `RapidFuzz 3.14.6` и зависимости. `pip check` не обнаружил конфликтов.

Команда: `python -X utf8 -m unittest discover -s tests -v`.

**35 сценариев прошли.** В тестах реальные сетевые запросы запрещены. Все операции с SQLite выполнены на временных БД, реальная БД в автоматических сценариях не использовалась. Дополнительно отдельно проверена миграция копии настоящего сохранения — см. `PRODUCTION_MIGRATION.md`. [Полный результат](test-results.txt).

## Сохранение и восстановление

Проверены круговой проход «SQLite + настройки + очереди → снимок → восстановление», целостность и число строк. Имитировались отказ загрузки, повреждённый скачанный файл, неподтверждённый архив, повреждённая новая версия и возврат к более ранней проверенной версии. Отсутствие БД/файлов не создаёт пустую замену.

Повреждённый архив не меняет существующую БД. Исправный снимок восстанавливается поверх повреждённого файла с сохранением прежних байтов отдельно. Работающий экземпляр блокирует замену БД. Незаконченная смена запрещает молча продолжить с устаревшим состоянием.

## Повтор отправки и отсутствие обычных дублей

Проверены недоступный рынок для неизменившегося объявления, повтор после появления данных, ошибка отправки с перезапуском процесса и однократная подтверждённая доставка. Повторная оценка той же цены не создаёт второй карточки; изменение цены сохраняет историю и отдельное событие. Состояние `sending` после аварии явно возвращается на повтор с отметкой неопределённой доставки.

Проверены `retry_after`, отсутствие немедленного второго сообщения после таймаута фотографии, отмена старой карточки при изменении цены, повторная оценка при изменении настроек. Сетевая неопределённость после принятия сообщения Telegram остаётся известной границей гарантии.

## История и смысл данных

На схеме исходной версии проверены повторяемая миграция, сохранение ID и истории цен, перенос прежних эвристик в отдельные поля, восстановление активных неуведомлённых записей без выдуманного обновления времени активности.

Удаление строки истории блокирует новый снимок даже при вставке другой строки взамен. Сохраняются исходные и изменённые описания/цены. Недоступность HTTP 404 не создаёт цену сделки; пустой HTTP 200 не закрывает объявление. Отчёт не содержит утверждения о «реальных продажах». Аудит БД проверен на отсутствие изменений файла.

## Пагинация и ротация

Проверены 95 уникальных объявлений на двух пересекающихся страницах, экранирование курсора, сохранение курсора после HTTP 429, возобновление обхода и отказ продвижения при неправильном ответе. Порог 5500 BYN остаётся в запросе.

Ротация сохраняет несколько последних версий и вручную названный оригинал. Повреждённый недавний снимок запрещает автоматическое удаление старых копий. Блокировка экземпляра освобождается при закрытии.

## Проверка команд и форматов

Отдельно выполнен настоящий локальный проход команд `runner --initialize --init-only → snapshot → restore-local → check → data_audit` на временной БД. Сети и Telegram в этом проходе не было.

Python-файлы компилируются; оба workflow разбираются как YAML; оба shell-скрипта проходят `bash -n`. Проверяется исключение БД, настроек, окружения и секретных файлов из Git. Скан известных форматов токенов не нашёл значений; он не является универсальным доказательством отсутствия любого секрета.

## Живой API Kufar

Выполнены три чтения без авторизации: первая страница — HTTP 200 и 50 объявлений, страница по курсору — HTTP 200 и 50 объявлений, одна карточка — HTTP 200 с объектом `result` и полем `price_byn`. Это проверка текущего формата API. Длительный сбор и полнота покрытия этим не доказаны.

## Что не подтверждено

Чтение настоящего `sniper.db` из GitHub Release и миграция его копии уже проверены. Две живые короткие смены подтвердили Telegram, загрузку новых снимков в GitHub Releases, их восстановление и автоматический запуск следующей смены. Ещё не подтверждены Linux `systemd`, перезапуск отдельного сервера, длительные задержки/лимиты Kufar и 24-часовая стабильность. Дополнительно все 35 сценариев прошли на Linux/Python 3.12 в GitHub Actions. Локально WSL-дистрибутива нет.

Точность цены сделки и доходность не измерены. В исходной базе предполагаемые продажи не могут заменить настоящие результаты сделок. Проверка на копии реальной БД пройдена. Проверка свежего последнего сохранения и контролируемый живой запуск пройдены; результаты — в `LIVE_ROLLOUT.md`.
